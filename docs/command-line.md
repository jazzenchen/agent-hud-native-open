# Command line

## Overview

Launch options, read-only probes, adapter commands and the MCP server of the standalone application. The same switches work on `build/Agent HUD Open.app/Contents/MacOS/Agent HUD Open` (after `make build`), on `swift run AgentHUDOpen`, and through Launch Services as `open "build/Agent HUD Open.app" --args …`. Unknown switches are ignored; probes and adapter commands run before the application object exists and never show a window. Applications that embed the libraries document their own parameters.

## Launch and display

| Switch | Effect |
| --- | --- |
| `--demo` | Use the sample data (`DemoUsageProvider`, `DemoData`) instead of installed clients; see [The sample](#the-sample). Preferences live in the separate `app.agenthud.open.demo` defaults domain, no report cache is written, and no adapters are installed. A demo saved with rows the sample no longer has starts over from the sample's rows and keeps its other preferences. |
| `--demo-tools` | With `--demo`, answer the [MCP tools](#mcp-server) from the demo, so an agent can arrange the panel on the sample while a person watches or records it; a layout saved there is kept in the demo's preferences. One process serves the tools' socket, whichever started first: a demo started with this switch answers every tool call until it quits, and the real copy started after it answers none, even once the demo has quit, until it is itself started again. Without `--demo` it changes nothing. |
| `--lang zh\|en\|system` | Force the interface language for this launch (`zh`, `zh-hans` and `cn` select Simplified Chinese). The choice is saved to the preferences in use. |
| `--show-settings` | Open the settings window after start. |
| `--show-stats` | Open the statistics window after start. |
| `--open-panel` | Start with the notch panel expanded. |
| `--show-onboarding` | Show the first-launch window even when onboarding is complete. |
| `--reset-defaults` | Remove the application's stored preferences before starting. |
| `--snapshot <dir>` | Render every screen at 2× to PNG files in `<dir>` from sample data, then quit; only a debug build renders, and a release build says so and quits. `AGENTHUD_SNAPSHOT_PREFIX=<name>` limits rendering to snapshots whose name starts with the prefix, for example `settings-`. |
| `--demo-script <name\|file>` | Play a timed scenario in the demo, and turn the demo on. `showcase` is built in: two agents start work, Claude asks to run the tests and is answered, Claude replies, Claude's session window crosses nine tenths used, the panel opens and closes, Codex replies, then it starts over. Any other value is the path of a JSON file; see [Recording](#recording). |
| `--demo-clock <time>` | Start the demo at this moment instead of now, and turn the demo on: an ISO 8601 date and time such as `2026-10-12T09:41`, local unless it names an offset (`Z`, `+08:00`), seconds optional. The demo's time runs on from there, so its dates, hours and "today" are the same whenever it is run. With `--snapshot` the stills are rendered at that moment. A value that does not read as a time is logged and the wall clock stays. |
| `--record <file.mov>` | Record the main display's HUD, and nothing else on screen, to a ProRes 4444 movie with a transparent background. `--record-seconds <n>` finishes the file and quits after that long; without it the file is finished when the application quits. `--record-fps <n>` sets the frame rate (60). `--record-region <x,y,width,height>` records part of the display, in points from its top left. |

`make demo` runs `--demo --show-settings`; `make snapshot` runs `--snapshot build/snapshots` (override the directory with `SNAPSHOT_DIR=…`).

Only one Agent HUD runs at a time, whichever application built on these libraries it is. A launch while another copy runs shows an alert naming the application that runs and quits before it reads preferences, opens the ledger or touches a client's settings. The lock is `~/Library/Caches/app.agenthud/instance.lock`, released by the system when its holder quits or crashes; a lock that cannot be created lets the launch run. Snapshots, probes and adapter commands run beside the running copy, and so does `--demo`; a launch with `--reset-defaults` does not, since the preferences it removes may be in use.

## The sample

`--demo` shows one sample, the same one the iPhone and Watch apps show in their demo, so a Mac and a phone recorded side by side agree. It is shaped as the providers shape real data: quota windows that belong to an account, models as token consumers, sessions that name the model they spend on.

| Part | What it holds |
| --- | --- |
| Claude, account Personal on Max | Current session 12% used, resets in 1 h 12 min; Weekly limit · All models 79%, resets in 5 days; Weekly limit · Fable 60% |
| Codex, account Personal on Pro | Weekly limit 49%, resets in 6 days; GPT-5.3-Codex-Spark 5h limit 18% and weekly limit 24%; two earned resets |
| DeepSeek | Balance ¥8.85, ¥0.01239 spent in the last day |
| Sessions | `s1` Build the iOS dashboard (Fable 5.1, running), `s2` Review App Store sandbox support (gpt-6-astra, running), `s3` Refine settings and colors (Opus 5.5), `s4` Run the regression suite (gpt-6.1-sol), `s5` Update the documentation (Sonnet 5.5), `s6` Package the Mac release (Opus 5.5), `s7` Check the release scripts (gpt-6.1-sol), `s8` Review the API integration (deepseek-v4-pro), `s9` Draft the release notes (gpt-6.1-sol, a day ago) |
| Tokens | 15 million a day before cache reads for thirty days, across Fable 5.1, Opus 5.5, Sonnet 5.5, codex-auto-review, gpt-6.1-sol and deepseek-v4-flash |

The running demo adds a row and a reading for every other vendor the app has artwork for, so the HUD carries a full queue. A figure changed in `DemoData` is changed in the iPhone's `DemoFleet` too, and the other way round; `DemoDataTests` pins the figures both show.

## Recording

`--demo-script` and `--record` together give the same take every time: `--demo-script showcase --record ~/Movies/hud.mov --record-seconds 45`. Add `--demo-clock 2026-10-12T09:41` and the statistics window's dates and hours are the same too, whatever the hour of the take; the menu bar's own clock and a permission card's count of seconds waited stay on the wall clock.

A script changes what the demo's own sources report, and the HUD reacts as it does to real ones; nothing is drawn by the script. Its JSON has `steps`, each with `at` in seconds from the start and `do`:

| `do` | Fields | What happens |
| --- | --- | --- |
| `work` | `session` | A demo session, `s1` to `s9` (see [The sample](#the-sample)), starts running, so its mark is at work. |
| `rest` | `session` | It stops with nothing to say. |
| `reply` | `session`, optional `message` | Its turn ends, which raises the reply reminder; the message is the reply's last paragraph. |
| `ask` | `request` | One of the demo's permission requests arrives: `demo-tests` (the test run the iPhone's demo asks about), `demo-edit`, `demo-build`, `demo-ticket`, `demo-read`. |
| `answer` | `request` | The client takes it back, as when it was answered in the client's own window. One answered on the HUD stays answered. |
| `quota` | `agent`, `used` | A window now reads this percentage used, named by its key: `claude-session`, `claude-weekly`, `claude-weekly-fable`, `codex`, `codex:spark:primary`, `codex:spark:secondary`, or another vendor's row by its id (`cursor`). The quota alert follows the usual rule, so a window the forecast already warns about raises nothing new. |
| `panel` | `open` | The usage panel opens or closes on the display the pointer is on. |

Beside `steps`, `running` lists the sessions already at work when the script starts (none by default), `used` sets readings that differ from the demo's own, and `repeatAfter` is the pause in seconds before the script starts over; without it the script plays once.

The recording is drawn in the application from the HUD's own windows as they are being shown, animations in flight included, so it needs no screen recording permission and no other window can appear in it. The picture has the display's pixel size, or the region's, and premultiplied alpha. A whole 2056 × 1329 pt display at 60 frames a second writes about 14 MB a second.

Core Animation's software renderer draws the frames, and `--snapshot` stills too, where the window server draws the screen; along curved edges the two differ by fractions of a pixel. The software renderer also adds something the screen never shows: an outline with continuous corners on a shape too short for them, a capsule above all, gets a straight line along each short side that runs past the tips. A reply's pill beside a separated dock, a Simple panel on the top or bottom edge and a plan badge are such shapes. Neither a recording nor a still shows the line: a still is drawn with those outlines' corners circular, and a recording draws the few points where a line would be that way, everything else as it is being shown.

## Read-only probes

| Command | Output |
| --- | --- |
| `--probe` | Prints where Claude Code's engine, Codex's engine and home, DeepSeek Harness's home and Node.js are, the agents in the settings and one step of reading Claude Code's transcripts; then one real account refresh (48 h of history) and one report with how long each took, `Quota windows: n; sessions: n; live: n; billing accounts: n`, the plans and notice, the discovered rows, each window's share used and reset, sessions by client, DeepSeek Harness's sessions and tokens, each balance and its estimated cost, the five newest sessions with their tokens and the values the vendor catalog does not name. Exits 0, or prints the error and exits 1. It issues the same provider requests as the running application and nothing else, and keeps what it reads in memory: it writes nothing to the usage ledger, removes or imports no earlier version's files and remembers no account identity. No conversation text and no credential is printed. |
| `--probe-open-agents` | Indexes the last seven days of local OpenCode, Kimi and Pi sessions and prints, per client, the session count, running count, distinct usage events, In / Out / Cache totals and the read status. No network requests, no transcript text, no credentials in the output. |
| `AGENT_HUD_PROBE_ADDITIONAL=1 swift test --filter AdditionalProviderTests/testInstalledSourcesReadOnlyProbe` | Read-only probe of the installed Antigravity, Cursor and Grok sources from the test suite; the test is skipped unless the variable is set. |
| `AGENT_HUD_PROBE_ANTIGRAVITY=1 swift test --filter AntigravityPermissionsTests/testInstalledAntigravityPermissionsReadOnlyProbe` | Reads Antigravity's native waiting permissions and prints their count. Sends no approval or rejection and prints no command, conversation text or credential. |
| `AGENT_HUD_PROBE_SESSION_USAGE=1 AGENT_HUD_PROBE_LEDGER=<ledger> AGENT_HUD_PROBE_REPORT=<report> AGENT_HUD_PROBE_OUTPUT=<file> swift test -c release --filter SessionUsageProbeTests` | Reads the breakdown of every session a retained `last-usage-report.json` lists from a consistent copy of a usage ledger (one `sqlite3 <ledger> ".backup <copy>"` makes), writes them to the output file as JSON with sorted keys, to compare two builds byte for byte, and prints the number of sessions and calls and how long reading all of them, and the largest alone, takes. The ledger itself is only copied, never opened. |

## Adapter commands

| Command | Effect |
| --- | --- |
| `--install-pi-observer` | Write or update the Agent HUD extension `extensions/agent-hud.ts` under the Pi directory (`PI_CODING_AGENT_DIR`, default `~/.pi/agent`), then exit. Existing Pi sessions need `/reload` once. A same-named file that is not Agent HUD's is left alone and the command fails. |
| `--attention-hook claude` | The handler Claude Code invokes for a notification: reads the payload from standard input, records the session's pending request, prints `{}` and exits 0 even when recording fails. |
| `--session-origin-hook codex\|claude` | Records the native session ID, host type, observation time and optional terminal destination at session start or prompt submission. For Claude Code it is also the [compaction hook](session-lifecycle.md#compaction-hook): a `PreCompact` payload records the session and the time it began compacting. Prints `{}` and exits 0 even when recording fails; it produces no completion, starts no interface and queries no account. |
| `--permission-hook claude\|codex\|qoder\|qoderCN\|qoderWork\|codebuddy\|workbuddy\|zcode\|qwen` | The handler the client invokes when it is about to ask whether a tool may run: forwards the payload to the running application and waits, prints back the decision the user gave, and exits 0. Codex CLI and Desktop share the `codex` handler. Prints nothing — leaving the client's own permission flow untouched — when the application is not running, the payload cannot be read, nobody answers before the client stops waiting, or Claude Code's session record shows the call was answered in Claude Code itself. It never initializes the interface or queries an account. |
| `--install-completion-hook antigravity\|cursor\|copilot\|codebuddy\|qwen` | Point the client's stop hook at this executable, adding it when it is missing; an Agent HUD handler already there, whichever copy wrote it, is taken over. Other hooks in the client's configuration are preserved. Fails, changing nothing, when this executable runs from a disk image or a translocated copy, and with an error for a client it does not know. |
| `--completion-hook antigravity\|cursor\|copilot\|codebuddy\|qwen` | The handler the clients invoke: reads the hook payload from standard input, stores a completion record when the payload describes a successful stop, prints `{"decision":"stop"}` for Antigravity or `{}` for the others, and exits 0 even when recording fails. It never initializes the interface or queries an account. |
| `--mcp` | Agent HUD's MCP server on standard input and output, one JSON-RPC message a line each way; see [MCP server](#mcp-server). A client starts it and keeps it running, and it exits 0 when its input ends. It must be the only argument. It starts no interface, takes no instance lock, queries no account and never starts the application; it only reads the lock, to tell an application that runs with its agent tools off from none running. |

A hook's flag this build does not know, any `--…-hook`, or a client name it does not know after one it does, exits 0 and prints nothing rather than starting the application: a client's hook names one executable path, a copy of another build may sit at it, and that copy started whole would rewrite every client's hooks to its own path.

Normal start-up already runs `SessionObservers.configure(executable:enabled:)` for installed clients with the `clientHooks` setting — pointing every Agent HUD handler at this executable when it is on, whichever copy wrote it, and removing them all when it is off — which also installs Claude Code's notification and compaction hooks and each supported client's approval hook ([approvals](hud.md#approvals)). Moving the application, or starting another build of it, therefore moves the hooks at the next start. Codex requires the user to review and trust a new or changed hook through `/hooks` before it runs; the HUD does not change hook trust or enable disabled hooks. The install commands exist for a first setup without launching the application ([notification hook](session-lifecycle.md#notification-hook), [compaction hook](session-lifecycle.md#compaction-hook), [completion hooks](session-lifecycle.md#completion-hooks)).

## MCP server

`--mcp` is how an AI agent reads the hover panel, sees a picture of it or of a screen's resting HUD, and proposes a layout for it, the shared one or a screen's own, which also sets the panel's session rows and token chart and says which agents that screen's resting HUD shows ([panel layout](hud.md#panel-layout)) and, for one screen, how that HUD is styled ([style drafts](hud.md#style-drafts)). Every tool takes an optional `screen`: a screen key from `get_panel`'s `screens` for that screen's own layout, or `all`, the default, for the shared layout. A key must name an attached screen or one Agent HUD keeps a layout of its own for, which may be away; any other is refused with the attached screens' keys and roles. The client that starts the process keeps it for as long as it wants the tools. The process answers the protocol itself, in revisions 2024-11-05 to 2025-11-25, which open with a handshake, and 2026-07-28, which has none, and hands each tool call to the running application over `mcp.sock` in the data directory: one connection a call, at most 10 s for the answer. The application serves calls only while Settings → Experimental → Let agents arrange the HUD is on, which it is not by default. While it is off a call comes back as an error result that says "Agent HUD's agent tools are off. Turn them on in Settings › Experimental.", and with no application running one that says "Agent HUD is not running. Open Agent HUD and try again."; the process tells the two apart by the instance lock, which it reads without taking. A `--demo` launch serves no calls and leaves the socket to the real copy, unless it is started with `--demo-tools`, which serves them whatever the switch says.

| Tool | Effect |
| --- | --- |
| `get_panel` | Returns the panel of the screen asked for as JSON and changes nothing: `screen`, the key or `all`; for a screen, whether it `usesSharedLayout`; `revision`, one number for every layout; `unsaved`, whether that panel shows a draft; `hasPrevious`; the `layout` in effect there, a screen's style draft among its `hud` fields, the `style` in effect, its `width` included, the panel's `height` in whole points at that width with that display's insets, the main display's for `all`, as the island measures it before opening, and whether it `scrolls` there, being taller than the display's height less 80 points, whether Settings shows reset countdowns (`countdownOnInSettings`), each section with whether the layout shows it and whether Settings has it on, and every block the panel has, the shown ones first in the panel's order, with its `key`, `kind` (`quota` or `billing`), name, `widget`, the `widgets` it accepts, `measures`, those its picker offers in picker order, the first shown first, `offeredMeasures`, every one its widget offers, whether a quota block shows its `countdown`, its `columns` where it is drawn in cells, as its line sets them, its `ringSize` where in rings, its `span`, `full` or `half`, as the panel lays it out at that width with that display's insets (a block the layout asks to take half a line takes the whole one where no half block is left next to it to share a line with, or where the halves would be narrower than 230 pt, and a hidden block is told the span it asks for), and the latest readings of its rows or balances; `sessions`, the session rows' `limit`, `agents` (empty for every agent) and `states` in effect, the `offeredAgents` that have sessions now, how many rows are `shown`, how many `more` the filter keeps, and `byState`, how many of the last day's sessions are `waiting`, `running` and `ended` before the filter, counts and agents' names alone, never a session's title, prompt, project, path or id; `tokens`, the chart's `period`, the `day`, `week` or `month` it opens with, its `agents` (empty for every agent), the `offeredAgents` whose models it can draw now, and the `total` of tokens it counts over that period; and `screens`, every attached display in the system's order, with its `key`, its `name` by role (`Built-in display`, `Main display`, `Display 2` and on, never the name the system or its owner gave it), its `mode` (`notch`, `dynamic` or `simple`), `edge` and `hasNotch`, whether its panel draws the `shared` layout or its `own` (`layout`), the `width` that layout gives the panel there (a dock on a side edge widens its panel to keep the content at least 404 pt wide, which the picture shows), whether that panel shows a draft (`unsaved`), its resting HUD's style in effect, every style field in `hud`, the settings with any style draft drawn over them, the `look` it draws now, its `appearance`, `dark` or `light` with `system` as macOS is set, its `material`, `solid` or `glass`, and its `transparency`, with a `note` where Reduce Transparency draws it solid and opaque ([look](hud.md#look)), and whether a style draft waits (`styleUnsaved`), the `agents` its resting HUD can show now, by vendor, and those it `shows` under its layout. A screen's `mode` and `edge` are those in effect, a style draft included. A row's name is the window's as the panel writes it, in the application's language; keys, notes and refusals are the same in both. It takes only `screen`. |
| `get_panel_image` | Returns a PNG picture of the screen's whole panel as the layout in effect there draws it, an unsaved draft included, and changes nothing. It is drawn off screen from the panel's own views at the width the island gives it, the layout's or a side dock's wider one, and that display's insets, the main display's for `all` and for a screen that is away, on the island's card in that display's [look](hud.md#look) with its rounded corners, at 2 pixels a point, or at the scale that keeps it within 2,400 pixels tall, without opening the panel or starting a read. It shows the panel's content alone: no glow, no notch, no event card and no line about a failed refresh. Account names are masked (`j***s@gmail.com`, `P***l`), each session row is named by its place, Session 1 and so on, with no title or project, and a reading's reason or a client's notice is drawn as placeholder bars ([panel layout](hud.md#panel-layout)). A JSON text block comes first: `screen`, `revision`, `unsaved`, `width` and `height` in points, whether it `scrolls` on its display, `pixelsPerPoint`, and a `note` that says the same in words, the scale-down included, and that glass is drawn as a stand-in where the panel is drawn in it: a picture is drawn off screen, with no desktop behind it. With `show` set to `hud`, the default being `panel`, it draws one attached screen's resting HUD instead, as it looks now with any style draft, as Settings previews it ([style drafts](hud.md#style-drafts)), and its text block says `screen`, `show`, `revision`, `unsaved` (whether a style draft waits), `mode`, `edge`, the `appearance` and `material` it is drawn in, whether the `glow` is in the picture, `width`, `height`, `pixelsPerPoint` and a `note`, which says glass is a stand-in too; `all`, or a screen that is away, is refused with the attached screens' keys. It takes only `screen` and `show`. |
| `set_panel_layout` | Proposes a layout as [it is stored](hud.md#interfaces-and-configuration): `blocks`, each with its `span`, `full` or `half`, `order`, `sections`, `hiddenSections`, `style`, whose `width` sets the panel's, `sessions` (`limit`, `agents`, `states`), `tokens` (`period`, `agents`), and `hud`, whose `agents` lists the agents the screen's resting HUD shows, the whole layout wanted, with anything left out at its default. A call with only `hud` style fields beside `screen` and `revision`, `reset` among them, leaves the layout as it is, saved or as a draft, the screen's own or the shared one, and the `note` says so; one that names a layout field, `hud.agents` included, or `from` proposes the whole layout. A screen with a notch that a proposal turns into a dock at the top centre is placed at position 0, clear of the notch, as Settings places it, and the `note` says so. With `all`, a style field is refused with the attached screens' keys. For a screen it proposes that screen's own layout, which leaves the shared one alone; for `all` the shared layout, which every screen without its own draws. What the layout `get_panel` returned holds for a block, a row or an agent that is away can be sent back as it is. `from` set to `default` or `previous` proposes the default view or the layout saved before the current one instead, and for a screen `shared` proposes that it use the shared layout again. For an attached screen `previous` also proposes the style kept with that version, as Revert to Previous restores it, as the screen's style draft, drawn as that version looked and listed by the fields that differ; Save writes it back as it was kept. For a screen that is away it proposes the layout alone, and the `note` says so. `default` and `shared` propose the layout alone, as the layout's Reset to Default and Use Shared Layout do: they drop a style draft and leave the style as saved. For one attached screen `hud` also takes `reset`: `true` proposes the screen's default style, the placement its hardware is given, dark and solid, and the default glow, as its style draft, drawn as the defaults and listed by the fields that differ, which Save writes as the HUD style's Reset to Default does, and none where the screen already draws the defaults; it is refused beside another style field, with `all` and for a screen that is away, and `false` asks nothing. With `revision`, the call is refused when the layout has changed, or Agent HUD has restarted, since the `get_panel` that returned it. The proposal is drawn at once as an unsaved draft, kept as what it changes; one that draws what the saved layout draws clears the draft, and for a screen that draws the shared layout one that draws what the shared layout draws keeps it using the shared layout, so the layout `get_panel` returned can be sent back unchanged. Returns the panel as `get_panel` does, with a `note`, which ends by naming the blocks the layout gives half a line that take the whole one there, and why: no half block is left next to it to share a line with, or the panel is too narrow there for two halves side by side. |
| `discard_panel_draft` | Drops the draft of the layout asked for, a screen's own or the shared one, so its panels show the saved layout, with a screen's style draft, so its resting HUD shows its saved style, and returns the panel. It takes only `screen`. |

No tool saves and no tool writes the settings: a person keeps a draft with Save in the panel. A proposal the panel cannot do as asked changes nothing and is refused whole, with every reason: an argument, a block property, a style property, a sessions or tokens property or a hud property it does not have, a value of the wrong type, a widget, measure, ring size, span, spacing, section, session state or period name it does not know, columns outside 2 to 6, a width outside 480 to 720, a session limit outside 1 to 10, an empty agent's name, a style field out of the range Settings keeps it in, an appearance or material name it does not know, the notch on a screen without one, a style field the mode the screen's HUD would have does not draw, a style field for `all` or for a screen that is away, a block or row key the panel does not have now, a widget the block's kind does not accept, a measure its widget does not offer, a countdown hidden on an API balance, columns on a block not drawn in rings or numbers, a ring size on one not drawn in rings, half a line for bar rows, which need the whole one, an agent the screen's resting HUD cannot show now (for `all` or a screen that is away, one no attached screen's can), an agent in `sessions.agents` that no session has now or in `tokens.agents` that no model in the chart has now, each named by its mark, a screen key that names no screen, `from` beside a layout, `previous` while there is none, or `shared` for `all`. A key or an agent the layout in effect or the saved layout already holds for a block, a row or an agent that is away is no such reason, as long as what is held for an away block comes back unchanged: the panel has nothing to weigh a change to it against. `get_panel` and `discard_panel_draft` refuse any argument but `screen`, and `get_panel_image` any but `screen` and `show`; `get_panel_image` is also refused, with the reason, where the application has nothing to draw the panel or the HUD with or the drawing fails. A result is one block of JSON text, which `get_panel_image` follows with an image block, `{"type": "image", "data": <base64>, "mimeType": "image/png"}` as every revision the server answers defines it; a refusal is an error result in English sentences. A request is at most 1 MiB, and an answer from the application to the process at most 16 MiB.

To add the server to a client, open Settings → Experimental:

1. Turn on Let agents arrange the HUD.
2. Pick the client.
3. Press Add.

Then ask a new session of that client to rearrange the HUD. The list has Claude Code and Codex where this Mac has them; Other copies the server's settings as JSON for any other client. Add and Remove run the client's own commands below with this copy's executable, only when pressed, and Agent HUD only reads the client's configuration to show whether the server is there. From a disk image or App Translocation there is no Add: move Agent HUD to Applications first. In a terminal:

```sh
claude mcp add --scope user agent-hud -- "/Applications/Agent HUD Open.app/Contents/MacOS/Agent HUD Open" --mcp
claude mcp remove --scope user agent-hud
codex mcp add agent-hud -- "/Applications/Agent HUD Open.app/Contents/MacOS/Agent HUD Open" --mcp
codex mcp remove agent-hud
```

`agent-hud` is the name the client lists the server under, and everything after `--` is the command. The entry is the client's own, so a moved application needs it added again. What a connected agent can read and change is in [data access](data-access.md#agent-tools).
